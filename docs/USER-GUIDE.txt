AI Usage Widget
==============

Start
-----
Double-click AIUsageWidget.exe (or START-WIDGET.cmd in the source folder).
Release zips include everything they need; a build from source uses the
.NET 10 Windows Desktop runtime installed on this PC.
Keep the executable and its accompanying files together in this folder,
for example %LOCALAPPDATA%\Programs\AI Usage Widget.
Launching it again brings the existing widget into an always-on-top view.
If you cannot find it, double-click SHOW-WIDGET.cmd. This brings it forward
and recenters it on the primary monitor. A taskbar entry is available when
the widget is in always-on-top mode. New installations start in this mode.

Controls
--------
Drag the title area to move the widget. Its position is saved.
The pin switches between Always on top and On desktop.
The refresh button refreshes everything; readings also refresh
automatically every 3 minutes.
Hover over a reset countdown to see the exact local reset date and time.
Each subscription has a card. Further limits take one line each. When the
cards are taller than the screen, scroll them with the mouse wheel.
Theme (three-dot menu): Dark (default), Light, or Match Windows.
The three-dot menu and the tray icon menu provide settings, Hide, and Quit.
When a 5-hour limit drops below 10% remaining, a Windows notification is
shown once for that window. Turn this off with Low 5-hour limit alerts.
Reset notifications are also enabled by default for Claude, ChatGPT/Codex
and Antigravity, including weekly and model-specific limits. Windows that
were not used before the reset are skipped. A fresh reading must confirm a
reset; the countdown reaching zero alone does not trigger a notification.
Click the notification to open the widget. Reset history survives restarts.
Simultaneous notifications wait their turn instead of replacing each other.
Turn Reset notifications off in the menu to cancel pending reset alerts.
The first reading establishes a baseline. Resets are detected on the next
successful refresh, normally within 3 minutes, even when the widget is hidden.
Sleep, offline access, provider backoff, and Windows notification settings
can delay or suppress alerts. Queued reset alerts expire after 30 minutes.
Start with Windows can be enabled in either menu; it is initially off.
Click the taskbar strip or the app's tray icon to show the widget.

Usage beside the clock
----------------------
The taskbar strip shows the Claude and ChatGPT logos (and the Gemini logo
when Antigravity is shown), each with a matching-color number: the
PERCENTAGE REMAINING in the shortest window (usually five hours). The
ChatGPT logo shows your Codex allowance; with several ChatGPT accounts it
shows the average of what each account has left (hover for each one). A dash means that a
reading is missing or the reset has passed and a fresh reading is needed.
Readings continue updating when you hide the desktop widget.

Both logos and percentages stay together in one compact strip just left of
the primary taskbar's notification area. The strip is an app-owned overlay;
it does not reserve taskbar space. If buttons fill that space or the layout
cannot be checked, it moves just outside the taskbar. It follows display
scaling, hides with an auto-hidden taskbar and during fullscreen apps, and
returns when the taskbar is available again. Vertical taskbars show it beside
the tray. Use Show taskbar usage strip in the menu to hide or restore it.
One normal app icon remains in the tray for alerts and access to settings;
the four separate logo/number entries are no longer used.
Hover over a logo or number for the provider, window, remaining percentage,
and reset countdown. Right-click any of them for the usual widget menu.

Reading the bars
----------------
Bars and percentages show REMAINING subscription allowance.
The shortest window, normally the 5-hour session, is shown large for each
service; longer windows such as weekly limits are listed below it.
Codex windows are labelled by the duration returned by the account, rather
than assuming every plan has the same limits. Multiple buckets are supported.
Missing readings show a dash. After a reset passes, the old percentage is
hidden until a new reading arrives. The app never assumes a fresh allowance.
When a weekly limit is used up, the shorter limits it covers show 0% too,
in orange, with "Weekly used up" and when it resets. No low-limit alert is
sent for a window that a used-up weekly limit already holds at 0%.

Renewal dates
-------------
The date at the foot of each card shows when the plan renews or ends.
For ChatGPT it is the paid-period end that ChatGPT recorded in the sign-in
("Paid until ..." in orange once it has passed). Claude and Antigravity do
not report it: click "Renewal date" to enter it. Clicking the date opens a
calendar: pick the day, choose Monthly, Yearly, or Ends, and click Save.
Escape or a click elsewhere closes it without saving.

Several ChatGPT accounts
------------------------
The main Codex sign-in (CODEX_HOME or %USERPROFILE%\.codex) is always
shown. Accounts signed in to Codex Subscription Router are found
automatically. To add another sign-in, run in PowerShell:
  $env:CODEX_HOME = "$env:USERPROFILE\.codex-second"; codex login
then choose three-dot menu > ChatGPT accounts > Add Codex sign-in folder...
and pick that folder. Tick or untick accounts in the same menu.

Antigravity
-----------
When the Antigravity CLI (agy.exe or antigravity.exe on PATH, or the copy
T3 Code installs) is found, an Antigravity card shows the Gemini 5-hour
limit, the Gemini weekly limit and the Claude and GPT group. The widget
runs the CLI's /usage command, which uses no model turn. It never opens a
browser: if the CLI is signed out, the card asks you to sign in there.
Turn the card off with Show Antigravity in the menu.

Claude
------
Claude usage is read from your Claude account through the sign-in that
Claude Code already has; no extra setup is needed. It covers claude.ai,
Claude Code, and SDK-based tools, including model-specific weekly limits.
The sign-in is read for each request and never stored or refreshed by the
widget. If it has expired, open Claude Code once to renew it.
The widget does not send Claude messages or consume model tokens.

Optional: run CONNECT-CLAUDE.cmd to also receive a reading after every
Claude Code response through its status line. The original status-line
command is saved and invoked by the wrapper; if that command fails, a
simple model/context status line is shown instead. All unrelated Claude
settings are preserved. If this folder is moved, run CONNECT-CLAUDE.cmd
from its new location.
To restore the previous Claude status line, run DISCONNECT-CLAUDE.cmd.
These scripts use the Node.js installation already present on this PC.

Local storage
-------------
Usage snapshots, settings, a short diagnostic log, and the original Claude
status-line configuration are stored in:
  %LOCALAPPDATA%\AIUsageWidget
A complete backup of Claude settings from before setup is stored there too.
The widget stores quota readings, not conversation content or credentials.
Codex authenticates through your existing Codex CLI login. If it is signed
out, sign in through Codex CLI and refresh the widget.

Desktop mode
------------
The widget stays below every other window, even when clicked, so it is only
visible where no app covers it. It keeps its taskbar button. Show desktop
(Win+D) hides it along with other windows. Your wallpaper is not modified.

Remove
------
Turn off Start with Windows in the menu, choose Quit, and run
DISCONNECT-CLAUDE.cmd. You can then remove this folder. Local usage data and
configuration backups can be removed separately if no longer wanted.

Source and validation
---------------------
The source is in the repository's src/UsageWidget folder; docs/WINDOWS.md
is the full guide. Run the following from the repository root:
Build: dotnet build src/UsageWidget/UsageWidget.csproj -c Release
Publish: dotnet publish src/UsageWidget/UsageWidget.csproj -c Release -o app
Tests: dotnet run --project tests/LogicTests/LogicTests.csproj -c Release
       dotnet run --project tests/CoreTests/CoreTests.csproj -c Release
       node --test tests/bridge.test.cjs tests/setup.test.cjs
Live check: AIUsageWidget.exe --check  (writes check-result.json)
Screenshots: AIUsageWidget.exe --render-demo <folder>  (sample data only)
